# 创建提交

## 收集与分析

1. 检查 `git status`、已暂存差异、未暂存差异及未追踪文件，不遗漏隐藏目录中未被 `.gitignore` 忽略的变更。
2. 列出所有拟提交文件并总结实际变更。不得夹带、丢弃或改写无关内容。
3. 生成英文提交信息：
   - 新功能使用 `feat:`，问题修复使用 `fix:`，其他变更使用 `chore:`；版本发布使用 `release: VERSION`。
   - 标题简洁，`feat:`、`fix:`、`chore:` 后以小写字母开头，建议不超过 50 个字符。
   - 正文使用 `- ` 开头的英文变更明细，每条以小写字母开头。

## 强制确认

执行任何 `git add` 或 `git commit` 前，必须展示完整提交信息、变更摘要和全部拟提交文件，并使用以下格式等待用户明确确认：

````markdown
=== 需要确认提交 ===

提交信息：
```text
[完整英文提交信息]
```

变更摘要：
- [变更摘要]

将提交的文件：
- [文件路径]

确认提交吗？请回复“确认”继续，或回复“取消”终止。
````

只有“确认”“是”“提交”或 `yes`、`y`、`confirm` 等明确肯定回复才授权提交；“取消”“否”或 `no`、`n`、`cancel` 表示取消。其他回复不构成授权，需再次询问。

确认后暂存已展示的全部变更，并使用展示过的完整信息创建一次提交。完成后报告提交哈希和最终状态；取消或未确认时不得执行提交。
